# Rust transfer translation proof

From the repository root, run `verification/rust-translation/scripts/setup.sh` once while online. Run `scripts/verify-rust-translation.sh` to import the release fixture, regenerate native Rust, run the independent comparison corpus and invoke the proof. The lower-level interface accepts original Rust, generated Rust, their expected SHA-256 digests, and an output directory, in that order. It stages a fresh offline crate containing the checked bytes and links both implementations via `include!`. Errors leave the raw transcripts in the output directory. Only a checked run produces `result.json`.

The proof uses Kani 0.68.0, its bundled compiler at Rust commit `8925ea358a0f265ca61026aadc7ecc506c545cbe` (nightly-2026-08-21), CBMC 6.11.0 and CaDiCaL. It gives each harness 90 seconds and an unwind bound of 64, including standard-library code. The stage uses Rust 2024, debug mode and checked overflow. Kani compiles MIR with its standard-library models, abort-on-panic semantics, enabled assertions, assertion reachability and unwinding assertions. The proof covers single-threaded calls, successful allocation and completed Rust observations. The production import lock separately identifies the native rustc and target. The proof establishes behavior under the verifier's compiler and semantics.

`transfer_equivalence` calls the independent transfer and the generated operation resolved by its public IRI on empty production BTreeMaps. It quantifies over the entire signed i64 amount domain and both equal and distinct request keys drawn from the specified literals. It compares the full error IRI and final key count, and requires a reachable SourceMissing cover. The reported number of unreachable internal checks includes dead paths from the standard-library implementations. A reachable unsupported intrinsic or a remaining unwind violation fails verification.

`populated_equivalence` compares three actual map entries, including a bystander, over arbitrary admissible balances and signed amounts. Its source and destination choices include present, absent, identical and distinct keys. In addition to the complete named outcome it compares both map lengths, the presence of every initial key and every row's ID, owner and balance. A successful result requires all seven covers (success and six named errors). The runner records a solver timeout as inconclusive and propagates other failures. A finite map and fixed strings leave arbitrary maps, renamings, arbitrary text, and bystander insertion beyond the specified domain open. The independent native corpus supplies separate outcome and error-atomicity evidence.

For the negative control, the runner moves only the generated NonPositiveAmount guard ahead of SourceMissing and uses the original production source unchanged. The symbolic witness is constrained to amount -1 with an empty map and distinct keys. Kani must fail exactly the named-result assertion. The runner executes the Kani-generated concrete playback test and checks that the same assertion fails. The output includes the modified production bytes, concrete test, raw transcripts, verifier configuration and digests. The separate native corpus exercises a partial-update mutant and compares its full state.
