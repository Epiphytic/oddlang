## Bridge CLI observations

The driver invokes the real executable under an unprivileged account with pipe stdin, separate pipe stdout/stderr, canonical disposable cwd and a fresh absent state root. The child environment is exactly `PATH=/usr/bin:/bin` and `LANG=C`, with umask `0077`. The driver sets the inherited open-file soft and hard limits to 256 and records its other inherited startup limits. The parent hard limit must be at least 256. Init uses the pinned native engine worker path, a fixed lowercase hexadecimal request ID, fixed synthetic server and allowed-principal IDs, and a JSON-escaped state root and cwd. Version 1 omits `storage`, `command_policy` and `allow_shell_command`. The request is UTF-8 JSON terminated by LF. The fixture stores exact expectations and the transcript stores each realized request, reply, state observation and final status. Byte channels in the transcript use a reversible Latin-1 byte-to-code-point mapping. All checked streams are ASCII in these cases. [Executable entrypoint](https://github.com/Epiphytic/marmish/blob/49fc705408a230bd0ad896248d08dbdd2faad05a/crates/marmish-prototype/src/main.rs) · [Processing handler](https://github.com/Epiphytic/marmish/blob/49fc705408a230bd0ad896248d08dbdd2faad05a/crates/marmish-prototype/src/lib.rs) · [Fixture](../../examples/marmish/portable-bridge/baseline.json) · [Original transcript](../../examples/marmish/portable-bridge/original.json)

| Case | Checked outcome |
| --- | --- |
| Argument rejection | `--help` exits 1 with empty stdout and stderr. The disposable state root stays absent. |
| Clean EOF | With no arguments or bytes, the process exits 0 with empty streams and absent state. |
| Partial frame at EOF | One unterminated `{` produces an exact LF-terminated stdout error with `id:null` and `invalid_framing`. Status 0, empty stderr, absent state. |
| Version 1 Init | The exact correlated success reply arrives while stdin is open. EOF leaves stdout/stderr empty and status 0. The frontend releases its lock and durable files stay present. |
| Rejected version, retry and duplicate | Version 0 returns the exact correlated `invalid_request` with absent state, then valid version 1 initializes the same process. Duplicate Init returns `invalid_request` with byte-identical file contents at the two live checkpoints. EOF exits 0 without a trailing reply. |

The state comparator requires an exact relative path set, types, ownership by the effective user and permissions. `state` and empty `state/jobs` are mode `0700`. The key, encrypted database and frontend lock file are mode `0600`. The frontend lock file is empty, and a nonblocking companion lock attempt observes it held while serving and available after EOF. The live database WAL and shared-memory files are present, private and nonempty. They are absent after EOF. The key record has the exact eight-byte magic `MRMSKEY1` plus 32 randomized bytes. Its complete bytes persist across EOF in the same case. No key material or file content digests are published. The database and live sidecars are recorded with observed lengths and compared as nonempty. Random key payload, SQLCipher page bytes/salts, timestamps, inode numbers and absolute ephemeral paths vary between runs. Directory traversal and report serialization sort paths for repeatability. Cross-stream ordering is unobserved because every checked stderr stream is empty. These checked effects describe the pinned profile and fixture; portable storage obligations will specify which details affect consumers.

The bridge startup source disables core dumps using `RLIMIT_CORE`. The replay records args, streams, status, filesystem footprint and observable lock checks. Child changes to resource limits, filesystem calls outside the disposable root, process tree, precise flush latency and syscalls have no independent trace here. The Init run uses an actual worker image for executable validation. Executed jobs, detach/recovery, control signals, network behavior and state interoperability remain open. Uncovered bridge operations are `token`, `submit`, `status`, `begin_input`, `write_stdin`, `stdin_eof`, `read_output`, `cancel`, `maintain`, `cleanup_ready`, `migration_commit` and version-2 Init (files, native and migrate-native). A host with an open-file limit of 1,048,576 produced `worker_unavailable` in the first Claude review. The pinned child limit avoids that failure in replay. The upstream cause remains open. Other open cases include maximum line boundaries, complete framing and schema errors, all overlapping error precedence, default handling over the remaining input domain, several pre-existing or unsafe roots, worker precondition failures, short reads/writes, broken pipes, concurrent instances, root rejection and configuration differences.

## Replay the pinned bridge gate

Run on macOS Apple Silicon with the pinned checkout and cached Cargo dependencies, from the Oddlang repository root.

```sh
upstream=/path/to/pristine/marmish
asset_dir="$PWD/examples/marmish/portable-bridge"
build_dir=$(mktemp -d /tmp/oddlang-bridge-build.XXXXXX)
(
  set -eu
  cd "$upstream"
  test "$(git rev-parse HEAD)" = 49fc705408a230bd0ad896248d08dbdd2faad05a
  test -z "$(git status --porcelain=v1 --untracked-files=all)"
  test "$(shasum -a 256 Cargo.lock | cut -d' ' -f1)" = \
    9c5f7dde5c0f7d340e22dbefaa8a1c6ddb94c119011ba3e49ac8044c9b4cb0b3
  cargo +1.97.1 build --locked --offline --release --target aarch64-apple-darwin \
    -p marmish-prototype --bin marmish-engine-bridge \
    -p marmish-engine --bin marmish-engine-worker --target-dir "$build_dir"
)
bins="$build_dir/aarch64-apple-darwin/release"
python3 -B "$asset_dir/verify.py" "$bins/marmish-engine-bridge" \
  "$bins/marmish-engine-worker" --report "$build_dir/bridge-observations.json"
```

The runner passes five observation cases and rejects two controls through the same process comparator. Changing the expected status of argument rejection from 1 to 0 fails on status. Moving the partial-frame reply from its stdout channel to stderr fails on stdout bytes. The executable hashes identify the archived build and can differ across build paths.
