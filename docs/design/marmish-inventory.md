## Counting declarations

A **lexical site** is one distinct upstream symbol ID at this pin. The ID includes its source path, lexical ancestry, declaration kind and occurrence. The source inventory unions potential Cargo module contexts across the three target triples and named feature profiles. It counts a site once if two Cargo roots include it. A field, its enclosing struct and an implementation method each contribute a site. The 5,849 retained sites include 2,058 fields, 723 enum variants and 1,966 functions. Fourteen workspace Rust files have recovered parses. Macro expansions and omitted declarations have unknown counts.

`denominators.lexicalUnion` reports the unit, observed count, declaration kinds, dispositions, per-Cargo-target kind counts, parse gaps and unknown additional sites. Per-target histograms overlap when a source serves multiple roots. The classified source count can support a ratio for the same explicitly identified lexical sites, kinds, configurations and pin. Compare additions, deletions and kind changes by ID before reusing a denominator.

For **compiled runtime units**, each target/profile pair has its own entry under `denominators.compiledRuntimeUnits`. Every count is presently null. A future compiled-unit ratio needs an identified target, feature/profile settings, compiler, expansion and runtime reachability criterion, and a complete numerator and denominator measured under those settings. A successful Cargo build and the framing signature check provide partial evidence for those settings.

## Test and package inputs

The archive joins `testSites` to `testApplicability[triple]` by path, line and test name. Each row identifies its Cargo target, applicable feature profiles, uncertain selections and ordinary or ignored status. The collector evaluates direct Rust test annotations and inherited module cfg for debug test builds. Across the three named feature profiles, Apple Silicon has 1,199 applicable test sites, including 36 restricted to macOS. Both Linux architectures have 1,172, including nine restricted to Linux. Five sites on each platform carry an explicit ignore attribute, including helper entrypoints. These are source selections. The baseline records executions independently. Macro-generated tests, runtime branches inside a test and conditional behavior of external fixtures require separate evidence.

`workflowTestSteps` records the workflow, job, step, runner/matrix, conditions and command digest for upstream Cargo, Python and Node test steps detected from their command text. This includes the separate macOS provider gate. Consult the named workflow for driver commands and inputs when exercising a gate.

`platformPackaging[triple]` binds the release and streaming candidate workflow files and packaging commands by digest. Each row records the target, runner, minimum runtime and signing mode. The two Linux targets specify glibc 2.39. The Apple Silicon target specifies macOS 15.0 and ad hoc signing. The inventory hashes tracked build/packaging entrypoints, manifests, lock, license collector, inspection script, packager and release template. The pinned Cargo graph and file table identify the broader source inputs.

The candidate packager consumes the three final product binaries and the collected third-party license file. Their final-byte digests are null until a qualifying packaging run observes them on the named platform. A source hash identifies the producer. On macOS the workflow signs each product binary before hashing and packaging. The release tool is recorded separately as the packager.
