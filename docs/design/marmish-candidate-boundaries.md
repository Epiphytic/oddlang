# Marmish candidate validation

`python3 scripts/marmish/qualify_candidate.py ORIGINAL_CHECKOUT CANDIDATE_GIT_DIR EMPTY_OUTPUT` runs on Apple Silicon macOS. The candidate directory is the committed output of the two-build reconstruction. Its sibling `first/project.toml` must match the published version-two assembly pin. The verifier compares every tracked path and mode with the frozen original and checks each generated Rust blob against its manifest entry and projection bytes. The three generated lexical ontology files may differ. Each native run checks its own immutable Git revision.

The original archive contains the 22 native command observations from Phase 5. The candidate repeats those commands in a fresh clone and build directory under the same Seatbelt profile, denied IP networking, private home and temporary directories. Its release build records its own commit and target. The comparison preserves the SHA-256 and size of each of the three product binaries. A binary hash identifies a source build that embeds its own commit.

The comparator reads Cargo's target identity from stderr and individual libtest outcomes from stdout. For nested child harnesses it reconciles declared test names and statuses with each target's unfiltered summary. It reports new failures, improvements, missing tests, newly appearing tests, changed ignore lists and changed command exits. Optional failure-line references point into the retained transcripts. Tool output and all six CLI help/version probes are compared byte-for-byte. Cargo metadata comparisons normalize the private run-directory names. A regression produces a populated `qualification.json` and exit code 3. A candidate with matching known failures retains the status `baseline failures remain`. A missing or malformed result fails verification.

The installed-feature run identifies observed local qualification-driver tests by their Rust module and records each status. A separate status probe queries an inactive layout with a pre-seeded receipt and lock in the disposable directory. It checks exit, exact JSON bytes, empty stderr and the fixture's final contents and modes. The expected result comes from the inactive-layout contract. The 22-command original archive predates this additional probe.

The host matrix covers native macOS Apple Silicon source builds. Linux x86-64 and ARM64, release packaging and real multi-host installed qualification remain unobserved. Historical release and interrupted-copy observations retain their recorded revision and source in the comparison report. The matrix runs offline and exercises no live release deployment, external identities or remote peer operations.
