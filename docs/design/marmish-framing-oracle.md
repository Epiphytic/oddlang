# Canonical base64 in the Marmish framing oracle

At Marmish revision `49fc705408a230bd0ad896248d08dbdd2faad05a`, the `marmish-core` entry in Cargo.lock selects base64 0.22.1. The last check in `ProbeEnvelope::decode` re-encodes successfully decoded bytes with the same `STANDARD` engine and compares the resulting ASCII string with the input payload. Removing this comparison alone preserves the observable result for this dependency and configuration. The preceding JSON, version and size checks also execute in the same order in both variants.

The `STANDARD` engine uses the standard 64-symbol alphabet, requires canonical padding, and rejects nonzero unused bits. Padding can occur only at the end. A full unpadded quartet is a bijection between four six-bit digits and three octets. For a final quartet with one octet, the second digit must have its low four bits clear and the quartet ends in two equals signs. With two octets, the third digit must have its low two bits clear and the quartet ends in one equals sign. These restrictions give each successful decode exactly one spelling, including the empty string. Concatenating the full quartets and optional tail preserves that uniqueness. The observation runner verifies the direct dependency and package checksum, then compiles a separate check against the base64 artifact from the same Cargo build. It exercises all 4,096 alphabet pairs followed by two equals signs and all 262,144 alphabet triples followed by one equals sign. For each spelling it checks acceptance against the unused-bit rule and checks exact re-encoded bytes on success. The portable table separately covers malformed lengths and padding, invalid symbols, trailing bits, bounds and error precedence through the public Marmish API. A dependency or engine-configuration change requires this argument to be reviewed again.
