# Rust type re-export façade, version 1

The optional `rust-facade-v1` producer recovers type paths exported by a Rust library root. Given the selected Cargo manifest and a mapping, import traverses the root's Syn AST and compares the observed module/type identities with the independent mapping. The named target library supplies one scalar public type identity per exported name. The current qualification covers non-generic public structs and enums.

For the pinned Marmish package, `marmish_core::{ConfigError, RelaySet, Retention}` resolves to its private `config` module. The other three exported names, `FrameError`, `Limits` and `ProbeEnvelope`, resolve to its private `frame` module. All six are independently checked. The upstream declaration inventory counts the two module declaration sites in this root. Re-export entries have a separate type-identity count. [Marmish mapping](../../examples/marmish/facade.toml)

## Accepted source and graph

The façade root contains private, out-of-line `mod name;` items and public `pub use name::Type;` or `pub use name::{TypeA, TypeB};` items. Each module must resolve to a regular `src/name.rs` and export at least one mapped type. Names must be unambiguous ASCII Rust identifiers. Literal documentation comments, whitespace, grouping and declaration order carry no façade semantics. Conditional and inline modules, path attributes, re-export chains, renames, globs, nested paths and additional root declarations fail import.

Standalone dependency-free fixtures can use local non-generic structs and enums with simple field types. Their bodies remain native inputs. The Marmish profile separately admits the exact pinned workspace manifest, library Cargo manifest, Cargo.lock and two audited sibling sources. The importer records the selected Cargo package, actual compiler, host, edition and hashes of all selected inputs. It uses the offline locked library check on Rust 1.97.1. New dependency-bearing layouts require an explicit extension of this validation scope.

`domain.ttl` uses canonical N-Triples in the `urn:oddlang:facade:` namespace. The root's `private-module` edge names a local module. A module's `public-type` edge names a module-qualified type with the same publicly visible identifier. The closed grammar and canonical round trip reject undeclared or ambiguous names, duplicate triples and embedded implementation text. `source-map.json` connects each statement digest to the source identifier's line, column, half-open byte range and span SHA-256. It binds source-file, graph and build digests.

## Verification and projection

Import first checks the unmodified selected library. For the identity check, a temporary library preserves its original root and sibling bytes and appends a private-name witness for every mapped type: a separate public alias pointing directly into the private defining module. The verifier compiles this instrumented source against the selected Cargo build's actual dependency metadata. A separate consumer crate imports the production library's public types and compiles forward and reverse assignments between each instrumented public type and its defining-module alias. The import lock records hashes of the constructed witness and consumer. This compiler check covers type identity, including which private module defines the type. It carries no claim about a sibling's runtime behavior.

The externally trusted root is SHA-256 of the exact canonical `import.lock` bytes. Supply it to `oddlang build module IMPORT OUTPUT --import-sha256 PIN` or `oddlang import verify IMPORT --import-sha256 PIN`. Verification checks the entire closed three-file inventory and its source and compiler witnesses. Projection emits only `lib.rs` and its version-1 `projection.json` receipt. An independent consumer can compile the projected root with the selected sibling modules after deleting the original checkout. Mixed-source assembly pins and reproduces this producer separately from the framing codec.
