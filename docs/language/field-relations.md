# Typed field relations

An `oddlang-field-relation-v1` graph defines portable field types and ordered comparisons on previously declared record types. Each type has a stable identity and a map from field IRIs to types. Values support booleans, unsigned integers, fixed bytes, byte vectors, text and references to declared types.

A relation names its receiver and an ordered list of typed arguments. In each step, a field operand selects the receiver or a record argument and one field. An argument operand selects one input. Comparison operands must have the same declared type. Named operand types declare equality explicitly. Every method argument must be used. A field or argument cannot serve as both sides of the same comparison. A relation without a `failure` returns a boolean.

A relation with a `failure` returns a typed result and stops at the first unequal comparison, returning its named mismatch error. A checked relation can also invoke a fallible method declared in `calls`. The receiver and ordered arguments must match the signature. A `check` step invokes a unit-returning method. A `result` operand compares the value of a fallible invocation. The generated binding propagates errors in step order and fixes the native error type in each call, without conversion. Procedures name argument IRIs when passing values to a call.

The Rust overlay supplies crate-local type paths, field names, native call names and method names. It binds each mismatch to a Rust error variant and optional static text argument. Record arguments are borrowed, opaque named arguments are passed by value and must declare Copy when passed to a fallible call, and byte and text arguments borrow slices. Byte and text fields and return values use owned vectors and strings. Equality borrows native operands. A comparison may directly use a checked return value without storing or subsequently exposing it.

The package component `field-relation` adds inherent methods to generated types. Its package entry has no reexports of its own. [Independent precedence fixture](../../verification/field-relation/verify.py)

## Compiler-backed recovery of direct conjunctions

Use the pinned Rust observer with the existing Cargo profile wrapper. For example, the unrelated verification crate selects `crate::Invoice::agrees` through `ODD_RECOVERY_FIELD_CONJUNCTION`. The observer resolves HIR parameter bindings, direct field projections and equality instances. It accepts ordered `&&` of `==` using supported integer or boolean equality, standard fixed byte-array and byte-vector equality, or local fieldless enum equality whose optimized MIR compares exactly the two incoming discriminants. It records one unresolved obligation for the selected method whenever an operand or equality proof falls outside this profile. Statements, local aliases, shadowing, macro-expanded method expressions and other overloaded equality are outside this profile.

The receipt contains the compiler commit, selected method, source line, Cargo-relative source inventory with raw file hashes, ordered field identities and proof kinds. Verification checks each compiler-read Rust file against its raw-byte hash, including files that define owners and comparison types. The wrapper pins the compiler and target Cargo profile. Keep the external checkout, dependency resolution and profile pin with the receipt. Recovery verifies a pinned receipt as evidence of that compilation. Reproduce the observation when changing the toolchain, Cargo configuration, dependencies, or other build inputs.

Run `oddlang recover field-conjunction CRATE_ROOT SOURCE EVIDENCE SELECTION TEMPLATE OVERLAY GRAPH`. The selection provides the stable relation IRI and the SHA-256 of both the selected source and the receipt. The template supplies a vacant boolean relation and a stable record vocabulary. The Rust overlay associates names with stable identities. A successful recovery populates the ordered comparisons and checks the normal graph invariants. Build the projected package using the resulting graph and target overlay. Receipt, source tree and recovery toolchain are provenance inputs for verification.

Run the unrelated native verifier with `python3 verification/rust-recovery/field-conjunction/verify.py target/debug/oddlang`. It compares independent native outputs for two source revisions, checks that an edited secondary Rust file invalidates old evidence, and exercises rejected equality and effects.
