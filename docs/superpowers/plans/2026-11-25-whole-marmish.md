# Recovering the whole Marmish distribution

Build installable native Rust executables from a versioned, source-free Oddlang contract in `Epiphytic/marmish-oddlang`. Start with a client talking to a daemon and running a command through a worker. Finish with every shipped role, public workspace API, helper and supported installation profile accounted for. Compatibility means another implementation can consume the same inputs, interoperate with existing peers and produce the same specified outputs, state transitions and effects.

Use upstream commit `af54339d250290490d62d4475a77539b7e739071` as the proposed release reference. The existing evidence is four commits older at `49fc705408a230bd0ad896248d08dbdd2faad05a`. The difference includes the installer and installed benchmark socket handling. Rebaseline before reusing results. [Upstream changes](https://github.com/Epiphytic/marmish/compare/49fc705408a230bd0ad896248d08dbdd2faad05a...af54339d250290490d62d4475a77539b7e739071) · [Existing role and platform inventory](../../design/portable-rust-boundary.md)

## What the extractor still misses

| Gap | What would close it |
| --- | --- |
| Identity and build context | Bind external symbols to exact Cargo package instances, aliases and path dependency content. Capture build scripts, generated inputs, cfg, proc macros and target/feature settings. Stabilize identities for impls, closures and generated items across unrelated insertions. Compare editions, re-exports and conditional public paths per profile. |
| Types and source API | Preserve ordered fields and variants, visibility scopes, lifetimes, ownership at API boundaries, generic predicates, associated types, trait impls and bounds. Compile unchanged positive consumers and fail expected negative probes on both sides. |
| Relationships and coverage | Recover or explicitly bound indirect calls, callbacks, trait dispatch, projections, implicit drops, closure/async bodies and foreign calls. Reconcile independent declaration and MIR evidence on the same build profile. Record a witness or a classified limitation for every mismatch. |
| Processing and effects | A call edge does not describe a retry, transaction or authorization rule. Recover portable state, validation/error precedence, ordering, cancellation, durable commit boundaries and external capabilities. Have a human review ambiguous rules against independent observations. |
| Breadth of evidence | The old stream inventory has 3,296 declarations, 9,534 relationships and 2,976 gap rows. Bridge binary and handler library have 8 and 987 gap rows respectively. These are per-owner observations, not counts of distinct missing features. Only the Data frame has qualified native Rust and TypeScript processing. Five bridge observations exercise the original. |

The independent stream comparison including macro expansions left 373 compiler-only and 72 rustdoc-only keys. Profile differences and span collisions complicate interpretation. Keep two explicit claims per release: structural fidelity for inventoried declarations/relations, and behavioral compatibility for qualified interfaces. A successful binary test cannot close an unresolved structural claim. [Compiler evidence](../../design/portable-rust-structure.md) · [Qualified Data scope](../../design/portable-rust-slice.md)

## Phases and gates

- [ ] **1. Freeze the release and its acceptance matrix.** Inventory all seven packages with Cargo metadata, all public libraries, feature-gated binaries, Python frontends, install scripts, packaged assets and external programs. Map each to owner, target, observed contract and test. Build original client, daemon and both worker entrypoints. Record macOS ARM64, Linux x86-64 and Linux ARM64, default, fault-injection and installed-checks where applicable. Archive independent transcripts, old state and sealed workloads. Define exact bytes for canonical formats, logical equality for randomized encrypted output, partial orders for concurrent events and explicit timing bounds where observable. Gate on repeatable original-to-original runs and mutations the oracle detects.
- [ ] **2. Recover and reconcile the workspace graph.** Extend the Rust compiler adapter and typed structure vocabulary in Oddlang. Resolve package-to-package references and profile-specific nodes. Add unrelated fixtures for each language feature. Independently enumerate public surfaces and private structure in scope. Exercise source mutations which add, remove or redirect declarations and effects. Publish coverage per package/profile, including unobserved edges and owner. Block exact-structure claims on unresolved rows. A private gap remains open unless an independently checked configuration or type-level exclusion rules it out for that cell. Absence from a sampled trace is insufficient.
- [ ] **3. Complete the reusable data and state contracts.** Recover all stream variants, codecs, windows, canonical JSON and core config/probe frames. Encode ordered guards, overflow/size limits, digest rules, time, duplicates, incremental input and partial failure as language-neutral facts. Preserve Rust bindings as a target overlay. Finish the earlier stream qualification, including alternate-library substitution and TypeScript conformance. Cross-read original and generated peers, compile consumers unchanged, fuzz boundaries and exercise recovery mutations. Gate on every declared stream and core obligation having a passing independent test.
- [ ] **4. Generate a thin installed system.** Specify generic file, process, socket, clock, random, key-store, encrypted transport and transaction capabilities plus portable orchestration rules. Land each Oddlang addition with an unrelated fixture. Keep Marmish policy, names, schema and commands in the companion graph. Bind proven native providers for SQLCipher, Marmot/MDK and OS services through optional library hints plus separately pinned build dependencies. Generate client, daemon and worker entrypoints, run one authorized remote command through real transport, persist its outcome, restart and read it. Exercise original/generated peers in both directions. This is the first product checkpoint.
- [ ] **5. Close every client, daemon and worker operation.** Expand engine, prototype, vault, native and MDK contracts across identity/setup, authorization and denial, conversation/relay, job admission, fencing, cancellation, spool, encrypted state, bridge v1/v2, copy/resume, rsync, cleanup and helper handoff. Cover native and legacy worker naming, keychain helper, Unix FD inheritance and line/IPC framing. Use per-role ownership and deterministic schedules plus real crash, reconnect, short-write, competing process, wrong-principal, stale-token and disk-full tests. Test state written before a swap and continued by the other implementation in both supported directions. Gate on operation-level closure for each applicable profile using staged installations.
- [ ] **6. Qualify clean builds, deployment and mixed releases.** Generate the complete first-party workspace from graph, lock and native provider selections in the companion repo. Build offline in a fresh isolated runner with upstream source, first-party generated caches, original executables and oracle unavailable. Audit dependency provenance and read access. Run acceptance separately against original/original, original/generated, generated/original and generated/generated endpoints, independently swapping workers, local CLI/daemon and bridge where supported. Exercise install, service start, upgrade, supported rollback, signing/verification and real platform key providers on all distribution targets. Include legacy Python tools, release/check tools, scripts and feature-only targets from the inventory with an explicit replacement or conformance test per artifact. Publish hashes, inputs, unresolved gaps and receipts for each supported cell. An unavailable host or provider keeps that cell open.

1. At the new pin, rerun the five bridge cases, stream oracle, Data qualification and structural extraction. Record toolchain, tree, lock, graph and transcript deltas. Preserve dev results for comparison and qualify shipped executables in release. Build the bridge, keychain helper, fault frontend, MDK probe and installed tools alongside the products. Establish original baselines on all three hosts before marking the freeze complete. Trace observable process, FD/resource limits, locks and writes outside state roots with OS facilities. Probe both the known 256 open-file limit and the high-limit worker failure. Capture deterministic local relay and legacy `wn`/`wnd` fixtures and pin their versions. Record upstream exclusions for interactive terminals, tmux, X11 and forwarding, and track experimental Tor separately.
2. On every supported target/feature cell, repeat extraction from two fresh directories with identical graph and semantic lock digests. Reconcile observations by semantic identity and profile, retaining source spans solely as evidence. Every comparator-only key needs a disposition and witness, including the old 373/72 sets on rebaseline. Unknown dispatch reachable from a selected operation blocks its qualification. Exact-structure closure requires zero unexplained mismatches and zero missing in-scope declarations or relationships.
3. Run the protocol gates on Linux and macOS before freezing portable behavior. Classify independent comparator disagreements as errors or documented representation freedoms. Include an unrelated project that uses the same generic vocabulary.
4. Run the first installed command on macOS and Linux with real providers and the pinned relay. Reject deliberate mutants that bypass authorization, lose the durable result or reroute the response. Observe peer identity, effect count and result after restart. Separate deterministic local fixtures from live integration smoke runs.
5. Import every named native command, hidden helper, bridge operation and v2 storage mode from the boundary inventory into the acceptance matrix. Diff that list against the new release. Stage install scripts and installed-check/fixture tools before operation-level qualification, including real macOS Keychain and Linux Secret Service trials. Gate each row on its expected exit/error channels, state and effects on each applicable platform.
6. Reserve archive layout, signatures, clean installation, upgrade and rollback with shipped artifacts for the distribution gate. Require the complete seven-package structural report alongside compatibility receipts. Label incomplete structural fidelity and failed or unavailable conformance cells separately. Whole-project completion requires both gates to pass.

Claude CLI reviewed the draft against the structural evidence and boundary inventory. The checks above incorporate its findings. The upstream revision comparison was verified separately through the GitHub API.

## Delivery and stopping rules

The framework team owns generic extraction, vocabulary, validation and native lowering in Oddlang. A companion project team authors reviewed contracts, target hints and release manifests. An independent verification team owns original binaries, unchanged consumers, mixed-version drivers and holdouts. Use subagents for those independent streams and Claude CLI in auto mode after each phase. Record findings, fixes, reruns and remaining coverage in the work ontology before advancing a gate.

No source text, AST dump, MIR instruction stream, original executable, vendored first-party crate or project-specific generator hook counts as a recovered contract. Keep provenance separately. Use normal third-party dependencies and audited OS/crypto providers. LLMs may propose missing rules or bindings for review. Each normative declaration must generate a test obligation with its stable ID, evaluator and result, including declared protocol errors and side effects. A missing rule, provider or test yields an explicit gap.

The principal feasibility risk is recovering intended behavior where only incidental implementation details are visible. Budget the effort by families of protocols, state machines and OS effects, then recalibrate after the installed command in phase 4 using actual authoring time, unresolved obligations and porting effort. If that checkpoint requires copying upstream implementation logic into provider shims or adding project knowledge to Oddlang, reopen the semantic design before expanding coverage. A finite qualification suite supports a versioned compatibility claim for tested profiles. Universal behavioral equivalence for arbitrary Rust remains unproven.
