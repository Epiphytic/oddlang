# Oddlang ledger implementation plan

**Goal** — Run the same modeled transfer in an interpreter and generated Rust, then evolve its stored data and events.

**Architecture** — Load local Turtle and overlays into one validated, typed model. Feed that model to the interpreter, target generators and version differ. Keep validation and execution independently testable.

**Implementation stack** — Build Oddlang as a Rust Cargo package with a library and an oddlang CLI binary. Use Rust libraries for Turtle parsing, SHACL validation, PostgreSQL access and binary Avro resolution. Check the chosen validator against the shapes used by the ledger fixtures. Commit Cargo.lock and run integration tests with cargo test --locked --offline after fetching dependencies.

**Spec** — [Ledger prototype](../specs/2026-11-25-ledger.md)

## Global constraints

Stable IRIs identify fields across versions. Builds operate offline and generate deterministic source. Balances range from zero through 9223372036854775807. Every failed transfer preserves both starting balances.

## Review focus

Exercise missing declarations, reordered triples, numeric overflow, duplicate account identity, and old events missing a newly required field. Run each task's tests before implementation to establish a failure and after implementation to verify the change. Commit each passing task independently.

## Milestone 1 — Compile one domain model

- [ ] **Load and check.** Create examples/ledger/v1/domain.ttl, target overlays, vocabulary/shapes.ttl and src/model.rs. Implement load_model(project_dir) returning typed entities, fields and operations keyed by IRI. Wire it to oddlang check. In tests/model.rs reject a missing required declaration, an unresolved import and conflicting target names. Report the offending IRI. Verify reordered triples and renamed prefixes yield equal models.
- [ ] **Emit Rust and SQL.** Implement oddlang build in src/main.rs with emitters in src/targets/rust.rs and postgres.rs. Generate a Rust balance with a private representation and checked constructor, plus a BIGINT column with NOT NULL and a nonnegative check. In tests/model_targets.rs compile the crate and apply the DDL. Submit −1, 0, the maximum and maximum + 1 to each boundary. Require matching acceptance, reject a deliberately wider source range during generation and compare output bytes across reordered fixtures.

## Milestone 2 — Run a state transition

- [ ] **Define and interpret the operation.** Extend the fixture and typed model with ordered guards, field reads, comparisons, checked arithmetic and a set of field assignments evaluated against the starting state. Reject duplicate assignments. In src/interpreter.rs implement evaluate(operation, state, arguments) returning either the new state or a named error. In tests/transfer.rs pin success (10, 3, amount 4 becomes 6, 7), same ID, zero amount, insufficient funds and destination overflow. Assert complete state equality on every failure. Pin the first declared failing guard when several fail.
- [ ] **Compile identical behavior.** Extend the Rust emitter to lower those primitives, compute both next balances and publish them only after checks succeed. In tests/transfer_targets.rs pass the same fixtures to a generated Rust harness and the interpreter. Compare errors and final states to explicit expected results. Change a guard in the Turtle fixture and check that both implementations change behavior without editing either backend.

## Milestone 3 — Evolve persisted data and events

- [ ] **Produce real v1 data.** Implement src/targets/avro.rs and an explicit event projection. In tests/evolution.rs write a binary v1 event using the emitted schema and insert its corresponding account into the v1 database. Read both back.
- [ ] **Diff by identity.** Add examples/ledger/v2 and src/evolution.rs. Match fields by IRI and compare target mappings. Produce a column rename for the same owner IRI. Require a declared migration strategy for unsupported changes. Apply the migration to the populated database and assert the original ID, owner and balance survive.
- [ ] **Check reader compatibility.** Generate the v2 event schema with the required currencyCode field. Check the old writer/new reader direction using schema resolution and the saved binary event. Require a diagnostic naming currencyCode when the default is absent and a decoded CAD value when present. Confirm the SQL-only rename leaves the event's owner field name unchanged.
- [ ] **Run the demo from clean inputs.** Add examples/ledger_demo.rs to check and build v1, run the transfer fixtures, persist the v1 examples, build v2, apply the migration to the disposable database and decode the old event. Run cargo test --locked --offline and cargo run --locked --offline --example ledger_demo with locally installed, pinned dependencies. Show generated files, decoded values and a deliberate validation error in the transcript.
