# Oddlang ledger implementation plan

Build a Rust Cargo library, CLI, emitters, interpreter, integration harness and demo against the [ledger design](../specs/2026-11-25-ledger.md). Commit Cargo.lock. For each task write the failing acceptance case first, implement, rerun and commit. Run the full suite with `cargo test --locked --offline` after `cargo fetch --locked`.

## Milestone 1 — Compile and inspect the domain

- [x] **Provision the integration environment.** In compose.yaml pin postgres:16.6 for the disposable test database. Document `docker compose up -d --wait`, the health check and ODDLANG_TEST_DATABASE_URL in the README. Use that URL in tests/support/db.rs and the demo. Fail with a setup diagnostic on missing URL, failed connection or server_version_num other than 160006. Allocate a unique schema per test and clean up after it. Cache the image and dependencies before the offline run.
- [ ] **Load and validate.** Create examples/ledger/v1/domain.ttl, its local imports and named target overlays. In src/model.rs implement load_model(project_dir) for oddlang check. Test missing fields, unresolved imports, conflicting physical names and unrepresentable ranges in tests/model.rs. Compare models and diagnostics after triple shuffling, prefix changes and blank-node relabeling. The typed loader owns structural validation.
- [ ] **Measure the graph's contribution.** In queries/impact.rq traverse declared dependency paths in reverse over merged reachable imports. Wire the query to oddlang impact in src/main.rs. In tests/impact.rs check the exact sorted set of IRIs for balance, including TransferFunds and Rust, SQL and Avro projections. Include an unrelated projection, a diamond import, and a nested import adding one projection. Compare with the equivalent TOML fixture and record the retain-or-switch decision using the design criterion before expanding RDF tooling.
- [ ] **Emit Rust and SQL.** Implement oddlang build in src/main.rs and src/targets/{rust,postgres}.rs. Generate Balance::try_from(i128), private storage, checked Account and constrained SQL DDL. In tests/model_targets.rs compile the output and submit -1, 0, i64::MAX and i64::MAX + 1 (computed in i128). Bind decimal text to PostgreSQL and explicitly cast through text to BIGINT so the server sees every input. Require reject/accept/accept/reject in both. Compare emitted bytes under all three graph rewrites.

## Language contract — prerequisite for Milestone 2

- [ ] **Publish the closed vocabulary and evaluation rules.** Write docs/language/ledger-core.md and examples/ledger/v1/transfer.ttl before writing an executor. Specify full IRIs, RDF term kinds, operand names, types, arities and cardinalities for declarations, projections, dependencies, arguments, existence tests, reads, constants, comparisons, addition/subtraction, guards and assignments. Define binding, integer widening and interval rejection, named errors, guard order, pre-state reads, simultaneous commit and assignment conflicts. Include a worked success and a competing-error trace using the design table. Pin exact expanded IRIs and operand order in a hand-authored expected lowering. In tests/model.rs reject blank guards, missing or duplicate priorities, duplicate targets, unguarded missing-account reads, unsupported nodes and cyclic expressions. Require stable named-owner diagnostics after relabeling malformed anonymous operands.

## Milestone 2 — Interpret and compile the transfer

- [ ] **Build the oracle first.** In tests/support/ledger_oracle.rs implement the design table over plain maps, ID strings and i64 amounts. Use destination headroom to decide overflow. Share only input/output serialization with the executors. Pin the 10/3 transfer of 4, each error IRI, simultaneous failures, untouched bystanders and complete state on failure. Use independent literal expected states for these cases.
- [ ] **Build the two execution paths.** In src/interpreter.rs evaluate the loaded operation against state and argument IDs. In src/targets/rust.rs lower the same primitives into a separately compiled function accepting a map and IDs. In tests/transfer_targets.rs compare each result and the entire resulting state to the oracle, including both-missing and same-ID inputs. Change the model's positive-amount guard to allow zero, predict the new result for distinct existing accounts, and test both engines against it. Also swap debit/credit operands in a well-typed fixture and verify the unmodified ledger oracle detects divergence on a valid transfer even if the engines agree.
- [ ] **Run boundary-weighted differential tests.** Batch at least 10,000 seeded cases through the compiled harness and interpreter. Mix random valid balances with 0, 1 and i64::MAX, vary missing/equal IDs, and weight amounts around zero, available funds and remaining headroom (one below, equal, one above when representable), plus i64::MIN and i64::MAX. Include successes and every guard failure. Compare exact errors and full maps with the oracle. Print seed and minimized counterexample for replay.

## Milestone 3 — Evolve the table and wire format

- [ ] **Prove the v1 round trip.** Implement event projection in src/targets/avro.rs. In tests/evolution.rs use the generated Rust type to insert an account, select it back into the checked type, encode that returned row with the generated v1 schema and decode into a checked v1 Account. Assert every field and retain the bytes, writer schema and populated row for migration. Encode a negative balance directly with the raw Avro schema and require domain decoding to reject it with the balance IRI.
- [ ] **Migrate the populated table.** Add examples/ledger/v2 and a v1-to-v2 transition fixture. In src/evolution.rs match fields by IRI and generate transactional rename, add, CAD backfill and NOT NULL statements. Require an explicit transition value for historical rows. Verify all migrated rows retain ID, owner and balance and read CAD. Compare columns, types, nullability, defaults, keys and checks with a fresh v2 schema after normalizing schema names. Require an insert omitting currency to fail and an explicit non-CAD insert to retain its value.
- [ ] **Derive and verify wire compatibility.** For v1 writer → v2 reader derive the verdict in src/evolution.rs before decoding. Check the same owner IRI maps to ownerName with reader alias owner, and currencyCode has the transition-derived reader default. In separate negative fixtures remove only the alias or only the default and require the differ to identify the owner or currencyCode IRI respectively. Confirm both failures independently with binary resolution. With both repairs, resolve the saved event into checked v2 Account and compare every field with the migrated row. Round-trip an explicit non-CAD v2 account from Rust through SQL and its v2 event. Pin a Rust Avro resolver that passes the actual alias case before claiming compatibility.
- [ ] **Run the demo.** In examples/ledger_demo.rs run check, build, impact, a successful transfer and competing failures, the populated migration and the saved-event read. Show the IRI diagnostic for a missing reader default. Run the full offline suite and `cargo run --locked --offline --example ledger_demo` with the pinned server reachable. Report the graph experiment separately from target conformance.

## Contract interoperability across projects

Use the ledger artifacts from the three milestones to test the contract in two ownership models. Reusable mappings for mechanical projections take inspiration from [ggen](https://github.com/seanchatmangpt/ggen/blob/d173cad5792e837bd4fec730d120c582b9bc5d4c/README.md). Keep the Rust interpreter scoped to the ledger experiment.

- [ ] **Package and pin contract releases.** Create v1 and v2 release fixtures with a manifest, ontology imports, wire rules, directional compatibility notes and portable JSON vectors. For the JSON API encode signed 64-bit amounts and nonnegative balances as decimal strings so clients can preserve their full range. Include the maximum balance, a transfer request, success and named error responses. Test offline resolution from a project ontology importing the release. Verify a workspace lock pins the full import closure, rejects changed bytes under an existing version, and reports a missing cached import. Keep Cargo.lock for Rust dependencies.
- [ ] **Verify one coordinated monorepo upgrade.** In a fixture with a Rust service and CLI, a TypeScript client, PostgreSQL and Avro, upgrade one workspace contract pin. Regenerate the affected structural artifacts from the shared release, build the consumers and verify the v2 currency field across projections. Run the populated database migration and old-event checks. Exercise the client with the maximum balance and a named backend error. Rebuild offline and compare output bytes.
- [ ] **Verify independent contract adoption.** Give a standalone Go client fixture only the release bundle and published client vectors. Run its native tests offline in an isolated directory with no Oddlang generator, Rust library or publisher checkout. Keep the client pinned to v1 while the publisher workspace advances to v2, then explicitly upgrade and check the v2 vectors. For an optional reviewed adapter, demonstrate a target lock referencing recoverable source and the exact contract, overlay and vectors it passed. Reject a modified source digest and replay the accepted revision without calling an LLM.
