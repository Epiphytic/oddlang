# Phases 1–2 · WebAssembly components

The first Wasm target is a synchronous Component Model world. An application can implement the contract using any guest language. Oddlang publishes WIT, stable declaration identities, behavioral obligations and portable cases. Consumers can use the WIT directly. A release's Rust host runner exercises the component through the canonical ABI. A package may use this target without adopting HTTP or WASI. [WIT reference](https://component-model.bytecodealliance.org/design/wit.html)

## Phase 1 · Publish and recover a world

**Owners.** The model worker owns `src/wasm/model.rs`, `src/wasm/wit.rs` and `docs/language/wasm-core.md`. The release worker owns `src/wasm/bundle.rs`, `tests/wasm_release.rs` and `contracts/wasm/`. The integrator owns CLI dispatch, dependencies and the work graph. Agree on the resolved-world and stable-identity map before parallel work.

- [x] Write two small independently authored fixtures. The production ledger world imports a read-only initial account snapshot supplied by its host once per instance. It exports account lookup and transfer (two account IDs and an s64 amount returning a typed result). Seed each instance through that import and query all fixture IDs, including missing IDs, using public lookup after each operation. A separate, independently pinned test world includes the production world and adds fixture-load and complete-snapshot exports for deeper state observations. Compile and inspect each world separately. Assert the production world exposes neither test export. The other is a record/list/option/variant echo world using Unicode strings and empty values. Include explicit declaration ordinals for parameters, record members and variant cases. Change the order of Turtle triples and require byte-identical WIT and identity maps. Change a variant case ordinal and require a different WIT layout.
- [x] Define the closed ontology profile for a versioned WIT package, interface, world, imported and exported function signatures, parameters, returns, signed integers, bool, string, list, option, record, enum, variant and result. Treat WIT names and semantic IRIs separately. Specify escaping, ordinal uniqueness and contiguous indices, checked bounds beyond WIT types and a stable diagnostic for unsupported constructs. Reject name collisions, raw core Wasm modules, resources/handles, async types and unpinned foreign packages. Allow external types through digest-pinned WIT package dependencies with tests for conflicting transitive pins.
- [x] Implement `oddlang wasm publish SOURCE DEPENDENCY_LOCK CACHE OUT` and `oddlang wasm import-wit WIT_DIR WORLD ID_MAP OUT`. Publish canonical WIT and its stable-IRI mapping beside ontology sources, rule version, obligation inventory, corpus and per-file digests. Model workspace and external-consumer lock resolution on the HTTP release path. Require exact manifest and dependency digests. Reuse the contained-path and verified-file readers. At this phase derive structural witnesses from the resolved world and bind authored behavioral cases to their declaration IRIs. Publication requires complete witness associations. Phase 2 executes those cases. For WIT-only imports, produce structural facts, require explicit IRI mappings or a caller-specified namespace for newly allocated identities, and report missing behavior/constraint evidence. Round-trip our fixtures through WIT to the same resolved interface. Preserve higher-level rules through the separately pinned ontology manifest.
- [x] Add a directional world diff that reports a change by IRI, the endpoint that must change, and the WIT surface involved. Use fixtures for a private ontology label change, exported function rename, swapped variant tags, and a new required host import. Pin old and new release manifests and test both host/guest directions. A structural-only diff returns `surface-equal` or `surface-changed`. Test its JSON and human output for absence of the word `compatible`, even for identical worlds. Only an attached, verified runtime witness for the same host/guest pins and direction may earn an observed compatibility verdict, scoped to the executed cases. Reserve broader WIT subtyping claims for rules with positive and negative runtime witnesses.
- [x] Gate Phase 2 with a pure-world toolchain spike. Build a Rust component exporting an integer echo with zero imports, extract its final world with `wasm-tools component wit`, require an empty resolved import set, and invoke the export from a Wasmtime linker with zero host definitions. Try a native component-producing target first. If it adds WASI imports, build a freestanding `wasm32-unknown-unknown` guest with pinned bindings and component type metadata, wrap it with `wasm-tools component new` and rerun the same test. If both fail, record the extracted world and linker failure and block Phase 2 pending a working pure build. Establish `cargo run --locked --offline --manifest-path verification/wasm-setup/Cargo.toml` using the successful compiler/target, component tools and Rust dependencies. Record versions, checksums and toolchain-specific build settings in a checked lock. Provide an offline verification path. Run `cargo test --locked --offline --test wasm_release`, including two clean publishes, stale pins, malformed WIT and reordered ABI members. Submit the phase diff, generated WIT and results to Claude CLI in auto mode. Resolve findings and rerun the affected gates before marking Phase 1 done.

## Phase 2 · Execute a contract across the ABI

**Owners.** The runner worker owns `src/wasm/runner.rs` and the Wasmtime host. The bindings worker owns `examples/wasm/` and guest builds. An independent conformance worker owns `tests/wasm_runtime.rs`, authored oracles and mismatch fixtures. The integrator owns the verifier entry point and the Rust Wasm qualification runner.

- [x] Build two Rust ledger guests against the same released WIT. One is hand-written from the ledger spec. It shares neither transfer code nor oracle code with the generator. For the other, emit ledger behavior from Oddlang's ontology and compile it behind a thin generated WIT binding adapter. Build both production and test-world artifacts for each. Run identical production cases through both guests and an independently authored Wasmtime host, comparing results to a third, separately maintained oracle. Run the additional fixture-load/full-snapshot checks only under the test-world release and artifact digests. Verify that test-world reports cannot satisfy production claims. Use pinned `wit-bindgen` guest bindings and typed host bindings. Use a componentized core-module build or a native component-producing target, whichever passed the Phase 1 spike. Inspect the *final binary's* world with `wasm-tools validate` and `wasm-tools component wit`. Resolve the extracted WIT and compare its allowed imports and required exports to the release before invoking it. Select a guest toolchain configuration that permits a pure world without ambient WASI imports. A WASI-dependent application must declare each required interface in a separately versioned world/profile. [Guest bindings](https://github.com/bytecodealliance/wit-bindgen) · [Wasmtime host bindings](https://docs.rs/wasmtime/latest/wasmtime/component/index.html) · [Wasm tools](https://github.com/bytecodealliance/wasm-tools)
- [x] Extend the portable witness format with `wasm.exporter` and `wasm.importer` roles relative to the component. An exporter case calls a guest export from an independently authored host. An importer case triggers a guest entry point and observes its outbound calls against a scripted host, including returned host values. The guest is the participant for both role claims. Independently exercise the host bindings using a probe guest. State the participant identity in the claim. Capture typed calls, complete ordered host transcripts, values, named results and traps in separate observations. Serialize i64 as decimal strings in JSON. Distinguish none from an empty list and a typed error from a runtime trap. Generate a witness for every applicable normative declaration/role, or require authored cases for uncovered obligations before publication. Use independent expected ledger state and errors, including an untouched bystander and a multi-error guard precedence fixture.
- [x] Give each case a fresh store, fixture state and explicit import bindings. Record module and runner digests with release pin, world, role, rule set and case IDs. Implement `oddlang wasm run BUNDLE LOCK CLAIM COMPONENT OUT` and `oddlang wasm verify-evidence BUNDLE LOCK CLAIM EVIDENCE`. Verify observations and complete coverage for the selected participant. Test refusal of stale evidence, missing cases, unprovided or undeclared imports and wrong world/ABI. Feed a faulty guest that traps on a named error and another that calls a host import twice to the same harness and require observable counterexamples.
- [x] For a hybrid stack, transpile the exact ledger component with pinned jco and exercise its published exports from TypeScript in both Node and headless Chromium. Supply the production world's initial-state import explicitly and use its public lookup and transfer exports. Record additional test-world observations against the test artifact only. Run the same portable cases, including signed 64-bit values outside JavaScript's safe Number range. Record the original component digest, jco version, generated module digests and distinct host evidence. Include both hosts in the offline verification command. [jco](https://github.com/bytecodealliance/jco)
- [x] Exercise the old/new host/guest matrix from Phase 1 through actual component loading and calls, recording link, type and behavior failures separately. Repeat in two clean directories with locks and compare generated WIT, source and case bytes. Record component digests, measuring binary reproducibility under the pinned toolchain independently of semantic equivalence.
