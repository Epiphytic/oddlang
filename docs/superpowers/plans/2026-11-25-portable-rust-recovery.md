# Recover portable contracts from Rust

**Goal.** Given a pinned Rust project and build configuration, extract its structure and observable behavior into Oddlang, then build native implementations from that release alone. Existing consumers must be able to supply the same inputs through the same interfaces and obtain the specified outputs and effects.

**Design.** Follow the [contract recovery design](../../design/contract-recovery.md). Use the Rust compiler during extraction. Ship a structural inventory, a portable contract, a public Rust API binding, and optional implementation hints as separately addressable graphs. Use Rust for Oddlang and the drop-in Rust target. Use TypeScript on Node for the independent portability demonstration. Each phase below has a named subagent responsibility. Use the subagent-driven-development workflow and have Claude CLI review the diff and evidence in auto mode after each phase. Resolve findings and record residual gaps in the work graph before advancing.

## What “exact” means

| Graph | Contents | How to verify |
| --- | --- | --- |
| Structure at a build pin | Workspace targets, modules, public and private declarations, containment, visibility, re-exports, signatures, fields, variants, traits, implementations, generic bounds, resolved calls, reads/writes, dependency operations and their data and effect relationships. Preserve declared order where meaningful. Distinguish dispatch candidates from observed targets. | Reconcile by identity, kind, endpoints and configuration against an independently produced compiler inventory. Trace-only observations carry the observed path. Unknown dispatch, expansion or reachability remains an explicit gap. |
| Contract | Stable identities for CLI commands, options, defaults, input/output channels, API operations, types, errors, protocol roles, effects and processing rules. Describe transformations through typed relations, constraints and state transitions, including guard precedence, arithmetic bounds, ordering and retry behavior as applicable. | Every normative rule has a defined interpretation and at least one independent observable obligation. Query from an input through the relevant rule and effect to its output or error. |
| Rust API binding | Public paths, types, signatures, trait and auto-trait commitments, feature gates and externally exposed dependency types, derived from public structure. Bind each item to its portable concept. | Compile unchanged downstream callers and positive/negative trait and feature probes. A crate identity exposed in a public signature can be mandatory for this Rust role. |
| Hints | A structure ID and role can reference a Cargo package, observed version/features, operation and interaction (e.g. bounded decompression), plus evidence. A target may select another library or algorithm satisfying that role. | Removing all hints or replacing a library leaves the contract digest and obligations unchanged. Per-target build locks record the actual choice. |

The published vocabulary admits typed facts, identifiers, protocol data literals, and references to evidence by digest and location. It excludes source snippets, token lists, syntax trees, instruction streams, serialized closures, opaque implementation payloads and arbitrary expressions evaluated as host code. Temporary compiler IR stays in extraction. Graph references may identify source locations for review. Builders never dereference those references. A contract rule earns its place through an observable distinction or a cited external promise. Private implementation detail belongs in the inventory. Target internal layout is free except where layout is an interface (for example, a wire record or a declared ABI).

## Phases and acceptance gates

### 1. Freeze the boundary and independent oracle — inventory and oracle agents

- [x] Freeze upstream Marmish at `49fc705408a230bd0ad896248d08dbdd2faad05a`, Cargo.lock, target triple, enabled features, toolchain and runtime environment. Enumerate the workspace's actual CLI entry points, public API and processing boundaries. Publish an applicability matrix by platform/profile and specifically mark Rust source API, protocol API, CLI, and any promised ABI.
- [x] Start with the complete public surface of `marmish-stream` (codec, wire, windows and copy protocol) and a separately labeled real CLI slice of `marmish-engine-bridge`: argument rejection, EOF and a successful version-1 Init on a disposable state root through its processing handler. Record exact request, state, streams, status and relevant host effects before implementing the importer. The stream crate itself has no CLI. Keep the remaining bridge commands and project surfaces on the matrix.
- [x] Under `examples/marmish/`, freeze vectors and transcripts from upstream, authored specification cases and an independent seeded driver. Revalidate the prior stream corpus against this pin. Cover normal, boundary, malformed and overlapping errors, state after failure, retries, chunking and mixed peers. For nondeterminism declare allowed outcomes, ordering and normalization field by field. Compare raw bytes everywhere the interface promises them. Seal holdouts before generating any target.
- [x] Gate: untouched original passes all applicable obligations and the driver detects a deliberately changed expected tag, status and transition. Preserve commands, environment, seeds, digests, provenance and the full list of uncovered surfaces.

### 2. Extract code-free structure — compiler and independent inventory agents

- [ ] Extend the Rust importer alongside `src/import_rust/`. Proposed entry point: `oddlang recover rust <manifest> --profile <profile> --out <bundle>`. Bind package, features, cfg, macro expansion, compiler and dependencies to the lock. Assign durable semantic IDs using package/owner/kind/name and reviewed identity mappings when a rename is ambiguous. Store build-local compiler IDs only as evidence mappings.
- [ ] Define the closed structural vocabulary first. Aggregate relationships at declaration level, retaining direction, relationship type and endpoints. Exclude per-statement sequencing and basic blocks. Recover structure from resolved compiler data, including macro-generated items and trait or generic calls. Independently check public paths with consumer compile probes and compare declarations and edges with a separately implemented inventory tool. Hand-audit a small unrelated fixture with re-exports, renamed dependencies, macros, features and dynamic dispatch. Detect one removed private item and one misdirected call edge even when public tests still pass.
- [ ] Gate: every expected item and edge in the selected slice maps to a graph fact or a named blocking gap. Only report exact structure for a pinned slice whose reconciliation has zero unknowns and mismatches. Test stable semantic IDs under formatting changes and distinct IDs for same-named items in different owners. Pin canonicalization, graph partitioning and literal encoding. Two fresh extractions and an equivalent triple reordering must produce identical canonical graph digests for the same pin. Reject source text in an identifier, token arrays, ordered statement lists, unknown predicates and oversized opaque literals. Require explicit type, bounded size and independent protocol provenance for binary constants.

### 3. Recover processing rules and library roles — semantics agent

- [ ] Specify each generic rule in `docs/language/` before adding recognition or lowering. Publish a closed, versioned rule grammar with reference evaluation and rejection tests before extracting any instance. Allow constrained relations and named transitions with defined pre/post-state semantics. Exclude general recursion, arbitrary user-defined operators and per-statement translation. Add a generic operation only with a specification and independently checkable examples. Start with bounded integer/byte relations, record layout, tagged variants, validation precedence, stream consumption, error mapping, state updates and declared external effects. Use typed data/control dependencies to associate source decisions with observable results. Represent a library interaction by what it consumes, produces, limits and can fail with. Pin an external specification or an authored role contract. Classify each outcome by exact value or an explicit equivalence relation. For process I/O classify byte/text channels, encoding, EOF, partial reads, flush points, output before failure, broken pipes, status, inter-stream order, environment, cwd and filesystem effects as normative or explicitly unspecified. Derive obligations for the normative cases. Record the observed crate and version as an optional hint.
- [ ] Emit draft facts with extraction evidence and unresolved obligations. Human or LLM proposals may complete ambiguous rules through a reviewed, pinned declarative overlay. Track automatic, reviewed and unresolved counts separately. Reject conflicting facts, unrecognized reachable behavior and opaque calls lacking a verified contract. Never infer an unrestricted rule solely from a passing example.
- [ ] Gate: queries recover the Data frame tag (5), field ordering and widths, offset/payload limits, applicable errors, window transitions and the chosen bridge request's processing path. Change a semantic value in Rust and re-import: the corresponding contract fact and obligation must change. Refactor an equivalent private helper: structural differences are allowed and the agreed contract still passes. Run the same importer on the unrelated fixture without a project-name recognizer.

### 4. Publish the release and implement both targets — release and target agents

- [ ] Publish the graph bundle and pins in `Epiphytic/marmish-oddlang`. Keep reusable vocabulary, validation and target lowering in Oddlang. Validate every rule against the phase-3 specification. Pin each graph independently and reproduce the normative release digest across clean builds. Automatically enumerate conformance obligations from normative IDs. Bind independent expectations from phase 1 to these IDs. Fail release on an orphan rule, missing oracle, unsupported mandatory operation or unapproved normalization.
- [ ] Generate a native Rust crate with the original public paths, signatures and supported trait bounds, plus the selected executable interface. Rust claims the Rust source API, bridge CLI slice, stream processing and both wire directions. Node claims the same CLI slice, processing and wire directions through its native API. Include role, version, configuration, obligations and gaps with each verdict. Implement the same protocol/processing model in TypeScript/Node using a separate target backend. Preserve native consumer expectations on Rust. Use a language-neutral driver for cross-language calls. Both targets build using only contract release, generic tooling, target bindings and pinned third-party packages in an isolated workspace. Supply only portable graph and role contracts to Node, and additionally the public Rust binding to Rust. Run both builds with the private structural graph withheld. Log every consumed digest and disallow access through provenance links. Withhold original source, binary, syntax archive and upstream dependencies containing the migrated component. Also withhold the oracle and vectors from target generation.
- [ ] Gate: compile unchanged Rust consumers, run unmodified CLI callers, exchange messages between implementations in both directions, and exercise the complete stream API on both targets. Repeat with hints deleted and substitute a different backend for one library role. For a role permitting alternative encodings, exhibit different valid bytes on the same input, identical decoded content and acceptance by original and replacement peers. Select such a fixture in phase 1 and document the governing rule. As a causal check, edit only the Data tag in a fork of the contract and rebuild both targets without Rust input. Both must emit the new tag and fail the original pinned interoperability case. Restore the pin and rerun. Record actual locked choices and compare observations including error paths. Reject a bundle containing embedded code and a build that tries to read upstream. No shared runtime kernel is required.

### 5. Qualify and expand to the project — qualification agent

- [ ] Drive original, recovered Rust, and Node targets using identical independent inputs and initial state. Run frozen, held-out and seeded generated cases, multi-step streams and mixed peers. Capture status, separate stdout/stderr bytes, public results, error categories, persisted state and allowed effect traces. Exercise boundary ±1, truncated frames, retries and invalid sequencing. Require the suite to detect wrong tags, error precedence, state changes after failure, CLI status and changed output channel.
- [ ] Publish per-surface coverage, source-to-graph reconciliation, unresolved behavior, manual modeling cost and exact reproduction commands. A finite suite establishes tested compatibility within the stated domain. Claim exhaustive equivalence only for domains where all cases or a sound equivalence proof have been checked.
- [ ] Expand the phase-1 matrix one dependency group at a time, repeating phases 2–5 for the remaining Rust packages, CLI commands, adapters and supported configurations. Inventory non-Rust entry points separately and model their observable boundaries when required by the project claim. A required host capability needs a native adapter and applicable integration evidence. A failed or untestable surface remains open. Whole-project completion requires every promised row covered, every mandatory behavior modeled, unchanged consumers passing, and a clean downstream build without original first-party implementation inputs.

**Review and evidence.** The independent oracle agent owns expected outcomes. The target agents see the published contract and documented target interface. The qualification agent controls holdouts. Each phase records its fixtures, commands, pass/fail report and Claude findings in `docs/design/` and links evidence from `docs/design/work.ttl`. Run scoped Cargo tests under `cargo test --locked --offline` plus native consumer and Node drivers. An implementation phase closes only after its gate passes. This plan authorizes no compatibility claim on its own.
