# Generic Rust round-trip experiment implementation plan

> Historical experiment. The current [contract recovery decision](../../design/contract-recovery.md) supersedes source fidelity as a product goal. The original execution instructions and checklist below describe the experiment as planned.

The experiment asks whether the same Rust importer and emitter can regenerate all of `marmish-stream` and an unrelated crate with no per-library translation rules. Build on the [Marmish qualification](../../design/marmish-qualification.md) and keep the existing executable framing graph and portable tests available. Those artifacts provide context and independent evidence for the older pilot.

## Specification

- Pin Marmish at `49fc705408a230bd0ad896248d08dbdd2faad05a`. Its `marmish-stream` crate has five tracked Rust sources and direct dependencies on base64, flate2, serde, serde_json, sha2 and thiserror. Start with native Apple Silicon and the upstream locked Rust toolchain. Record the exact selected features, target and Cargo commands for each claim.
- Use a versioned, queryable Rust syntax graph as the regeneration input. Represent nodes, token kinds and spelling, trivia, and ordered children with contiguous zero-based indexes. Use sorted canonical N-Triples in `syntax.ttl` with named nodes. Use stable file-relative identities and a separate semantic index for definitions and references. Individual literals, comments and macro tokens can retain their text. Opaque files, item bodies, or arbitrary source snippets as fallback are disallowed. The emitter must traverse and validate the graph. Byte identity is a fidelity check. An independent syntax edit must also change a compiled observable.
- Keep compiler-resolved facts distinct from syntax. Preserve unexpanded macro calls and inactive branches in the graph. Let Cargo and Rust run the original locked build pipeline on regenerated files. Export a versioned compiler report for the active configuration. Mark inactive branches unresolved for that build.
- Preserve the existing workspace and dependency names, public API, source locations where source-visible semantics require them, and compile-time inputs. Retain manifests, locked third-party code and declared non-Rust assets. Any crate-owned generated Rust activated by the claim must be inventoried and reproduced by a locked build step whose first-party sources are also regenerated, or the claim stays open. Report such generated units separately from graph-emitted source.
- Measure completeness independently from the importer. Freeze the crate-owned tracked Rust paths and real compiler-observed Rust inputs before importing. Record definitions by configuration and mark unresolved counts explicitly. Require 100% reconciliation of stable compiler dep-info for all claimed invocations. Report any compiler-semantic inventory from a separately pinned nightly under its own configuration and provenance. Require every selected input to have a verified producer, including all five known tracked paths. A missing source, unsupported construct or unknown active input blocks complete qualification. Work done to translate the crate is distinct from application-wide coverage.
- Treat same-language regeneration, coverage of an independent wire corpus and any portable semantics recovered as separate claims. The syntax graph does not itself create application contracts. Leave other Marmish crates, other platforms, arbitrary Rust support and universal behavioral equivalence open unless separately measured.

## Phase 1 · Freeze the experiment

**Owners.** Baseline agent owns `scripts/marmish/stream_baseline.py` and its receipts. An independent oracle agent owns `examples/marmish/stream-vectors.json` and a small downstream Rust driver. The integrator owns CLI and graph formats and the work ontology.

- [ ] Freeze the pinned crate's tracked Rust paths and identities from Git, then record upstream `cargo test --locked --offline -p marmish-stream`, `cargo check --locked --offline -p marmish-stream --all-targets`, and the release build of the package. Record full named test outcomes and actual Cargo invocations, including features and crate dependencies. Capture compiler dependency information and build producer inputs using the existing [closure audit](../../language/workspace-assembly.md) as a starting point. Keep the original and candidate under equivalent environment and source path semantics. Use independent clean target directories and the same remapped logical source roots and rustflags. Freeze original `--list` output by Cargo target and hash the inline test modules by source span. A separately compiled inventory baseline pins the real inputs. Add an undeclared input canary.
- [ ] Spike the compiler inventory before implementing the importer. Collect stable Rust 1.97.1 dep-info for the native acceptance runs. Prototype a separately pinned nightly compiler-side semantic export and compare its input closure with 1.97.1. If that comparison diverges, retain both reports and leave compiler-semantic coverage unresolved. Never use the nightly as evidence for the stable native build. Pin an edition-2024 lossless parser in the spike after verifying the raw-byte controls in the unrelated fixture. If an adapter cannot preserve those inputs, stop the spike with the failing fixture before proceeding.
- [ ] Freeze an unrelated fixture before implementing the importer. Use a small crate outside Marmish with a different pinned third-party proc-macro dependency staged into the offline Cargo cache, generic trait dispatch, and complementary `cfg(feature = "extra")` and `cfg(not(feature = "extra"))` branches. Add edition-2024, nested comments, raw strings, macro punctuation adjacency, `file!()` and `line!()` controls, plus distinct CRLF, BOM and shebang files. Preserve any parser-normalized byte details through typed trivia or file metadata. Exercise both configurations. The oracle agent owns the fixture and expected behavior and identifies one small observable mutation.
- [ ] Derive exact stream wire expectations from a reviewed encoding description and an independently maintained driver. Cross-check against the original before freezing. The regenerated inline tests are a separate observation. Cover valid encoding and decoding, boundary lengths, malformed or truncated input, first error where specified, and stateful window or checkpoint observations supported by the public API. Freeze names and expected bytes/errors before testing generated code. Keep the driver identical across original and rebuilt variants and observe mixed original/candidate directions where the wire format permits.

## Phase 2 · Implement generic source recovery and generation

**Owners.** Importer agent owns `src/rust_roundtrip/import.rs`. Emitter agent owns `emit.rs` in the same module. Independent verification agent owns `tests/rust_roundtrip.rs`. The lead owns shared graph types and CLI integration.

- [ ] Specify canonical serialization and graph validation in `docs/language/rust-roundtrip.md`. Use a lossless Rust parser with a small locked adapter. Reject parser error nodes, invalid schema versions, missing or duplicate paths, cycles, shared syntax children and invalid token or child ordering. Independently lex each leaf as exactly one token of the declared kind, including trivia, and require balanced, structured macro token trees. Reparse the full emission and require the same structured graph. Reject a raw item body disguised as a leaf. Preserve macro token adjacency and raw file fidelity, including a fixture that would detect loss of whitespace or line boundaries. Keep dependency names out of implementation dispatch.
- [ ] Implement `oddlang import rust-tree MANIFEST PACKAGE OUTPUT` and `oddlang build rust-tree BUNDLE OUTPUT --bundle-sha256 PIN`. Import writes `syntax.ttl`, `sources.json` and `bundle.lock`. `sources.json` inventories paths and output hashes. The canonical lock binds the schema version, graph and inventory. Require a caller-supplied lock digest before emitting Rust. Build stages a complete output and publishes only after verification. Use two named clean runs and compare canonical graph and emitted bytes. Shuffle triple order and require the same canonical bytes after normalization. Exercise corrupted paths, omitted files and a stale lock. For the independent edit test, recompute the inventory, regenerate the semantic report for the modified source and create a new authorized lock. Assert the emitted program changes the expected observable. Reject a stale semantic receipt by requiring its source and build digests to match when assembling qualification evidence.
- [ ] Regenerate the unrelated crate and all tracked `marmish-stream` Rust sources without accesses to the original sources, source blobs or caches of previous outputs. The importer reads original sources during capture. Isolate emission and subsequent builds on macOS with Seatbelt using the existing closure audit as a starting point. Deny reads of the original checkout, its Git object database and cached output roots. Allow pinned third-party source roots, declared reconstructed workspace inputs and pinned toolchain and SDK roots. Probe denied reads using canaries in the original checkout and Git object store. Build and test the unrelated crate with and without the feature. Re-run with renamed package and dependency aliases, and scan production importer/emitter sources for names from both fixture manifests, including `marmish`, `base64` and `flate2`. Review each match and reject fixture-specific behavior.

## Phase 3 · Resolve and close the build inventory

**Owners.** Compiler agent owns a separately pinned `verification/rust-inventory/` adapter. Integration agent owns the worktree-reconstruction runner. Independent verifier owns completeness and the source isolation tests.

- [ ] Implement the compiler inventory interface selected in Phase 1. Identify per-invocation root, crate identity, selected cfg, active source and generated input, type and call resolution status, and macro expansion origin. Compare exported inputs with compiler dep-info and include a generated-source and feature-toggle control. Keep version-sensitive compiler dependencies in the adapter. If active inputs or resolution cannot be reconciled, publish the discrepancy and leave compiler coverage open.
- [ ] Define `rust-inventory.json` and per-configuration receipt keys. Count unique tracked paths once, count compiler definitions per configuration, reconcile macro-generated items with their origins, and mark indirect calls and unresolved facts explicitly. Reuse the original receipt when checking the candidate, with source paths normalized only by a documented relocation rule. Preserve existing same-language projections and portable contracts.
- [ ] Assemble a clean workspace using the graph emitter as the only producer for tracked `marmish-stream` Rust files. Check that the withdrawn source files and their stored copies are inaccessible, including from build scripts and tests. Record dep-info environment dependencies and compare them alongside paths and hashes. Run the locked upstream commands against the resulting workspace. Compare the exact inline test span hashes, named test membership including ignored tests, and outcomes against the freeze. Test that removing `copy_protocol.rs` and introducing an undeclared compiler input each fails the qualification gate.

## Phase 4 · Compare behavior and decide

**Owners.** Validation agent runs the frozen independent driver, upstream suite and controls. The lead owns the evidence record and decision.

- [ ] Execute the frozen comparisons against both builds. Record full results for every case, the upstream named tests and exact wire bytes where specified. Record executable paths and SHA-256 immediately before running the independent driver. Reject a candidate receipt with the original driver executable substituted. Include at least one build-valid protocol mutation that the independent oracle catches. Replay in a clean checkout, including original and candidate runners with separate source trees. Pin archive, graph, compiler inventory and binary identities.
- [ ] Report tracked Rust paths regenerated over known required paths, active compiler inputs accounted for, named test results, protocol results and unrelated-crate outcomes. Record all code or configuration written solely for Marmish, grouped by importer/emitter, build setup, and contract fixtures. The first group must be empty. Group remaining workspace limitations by missing general capability and give a low-confidence estimate for the next substantial crate based on observed effort.
- [ ] Advance to another Marmish crate only after complete `marmish-stream` coverage in the declared configuration, matching required observations and an unrelated crate passing through the same implementation. If any gate fails, record the first missing capability with a reduced case and distinguish generic engineering from project-specific setup. Full application translation remains a separate work item.

At each phase boundary, run the relevant locked tests and use `claude -p --safe-mode --permission-mode auto` in a disposable checkout. Ask Claude to try falsifying the claimed coverage and explicitly look for source passthrough, hidden fixture rules, missing compiler inputs, and a comparison using the wrong binary. Resolve any finding that could invalidate acceptance, or record a reproducible check that disproves it before proceeding. Record commit, review verdict, evidence and blockers in `docs/design/work.ttl`.

Claude CLI auto review requested stricter controls for inline tests, token validation, toolchain provenance and build isolation. The follow-up found no blockers. Its remaining clarifications are incorporated above. The [experiment report at the pinned implementation commit](https://github.com/Epiphytic/oddlang/blob/e5af0cc48e386806a21a54765ef9318284b281be/docs/design/marmish-stream-experiment.md) records the results and their scope.
