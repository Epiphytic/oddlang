# Marmish qualification, phases 5–7

These phases follow the Wasm component and Rust import milestones. They use Marmish as an independent consumer with its own Cargo workspace, toolchain, dependencies, tests and ontology. Freeze source revision `49fc705408a230bd0ad896248d08dbdd2faad05a`. The implementation takes place in Oddlang with two disposable Marmish checkouts. The original is the behavioral reference. The candidate is built from an Oddlang project manifest. The plan calls for no upstream release. [Marmish source](https://github.com/Epiphytic/marmish/tree/49fc705408a230bd0ad896248d08dbdd2faad05a)

## Phase 5 — establish the source inventory and baseline

- [x] **Inventory agent** owns `examples/marmish/project.toml` and a generated inventory. Enumerate Git paths and modes, Cargo targets, features and cfg for all seven workspace members. Classify first-party runtime symbols as imported, retained native or unsupported, with reason, stable ID, source location and target. Classify tests, build inputs, external libraries, generated artifacts and static assets separately. Seed source references from Marmish's checked-in inventory. Its call edges are lexical and its parser reports recovery. Verify resolved signatures and reachable dependencies against the selected Cargo build. An unclassified file, unresolved reachable symbol or silent fallback must fail a completeness claim. [Marmish ontology scope](https://github.com/Epiphytic/marmish/blob/49fc705408a230bd0ad896248d08dbdd2faad05a/docs/ontology/README.md)
- [x] **Baseline agent** owns `scripts/qualify-marmish.sh baseline` and a machine-readable table of observations. Fetch and cache the pinned git dependencies, Cargo packages and Python tooling once. Capture `rustc -Vv` (Marmish pins 1.97.1), target, lock digests, flags, tools and environment. Check source ontology using the upstream immutable-tree check. Run these commands inside both workspaces, with network disabled after preparation. For each of Linux x86-64, Linux ARM64 and macOS Apple Silicon, also inventory upstream platform-specific tests, ignored tests and candidate packaging inputs.

  ```sh
  uv run --locked --python 3.12 --project tools/code-ontology python tools/code-ontology/index.py check --ref HEAD
  cargo metadata --locked --offline --format-version 1
  cargo test --locked --offline --workspace
  cargo test --locked --offline -p marmish-native --features installed-checks
  cargo build --locked --offline --release -p marmish-native --bins
  ```

- [x] **Integration agent** records public Rust exports, wire bytes, errors, CLI outputs, releases and platform/feature scope. Seed independent expected results from the upstream core contract tests and written framing semantics. Record a baseline failure or missing platform as such. Marmish documents interrupted-copy qualification failure, historical macOS cleanup uncertainty, and gaps in Keychain/Tor coverage against particular revisions. Re-establish evidence for this pin before attributing a failure to regeneration. Freeze the table before any cleanup or code generation. [Upstream tests](https://github.com/Epiphytic/marmish/blob/49fc705408a230bd0ad896248d08dbdd2faad05a/crates/marmish-core/tests/contracts.rs) · [Qualification history](https://github.com/Epiphytic/marmish/blob/49fc705408a230bd0ad896248d08dbdd2faad05a/docs/validation/v0.3.1-c2-validation.md)
- [x] Claude CLI auto review checks denominators, baseline identity, platform coverage and repeatability. Resolve findings and record commands, outcomes and gaps before phase 6.

The default local report covers only macOS Apple Silicon after its tests run. Register the two Linux targets as unobserved until fresh baseline and candidate evidence arrives from separate disposable native x86-64 and ARM64 Linux CI runners matching Marmish's glibc floor. Carry this status through release reporting. A build for another target or an archived upstream report cannot close its runtime obligations.

## Phase 6 — implement the features Marmish actually requires

- [ ] **Assembly agent** implements generic mixed-source workspace reconstruction with an explicit file manifest, public API overlays, relative module paths, feature/target conditions, file modes and pinned dependencies. Freeze the CLI and manifest schema before implementing the codec. First test on a two-crate fixture, then compile an independent Rust consumer against the generated Marmish module. The phase-3 command `oddlang import rust <manifest-path> <mapping.toml> <output-dir>` supplies the module graph, source map and lock. Extend `oddlang build` with a graph-to-module projection, proposed invocation `oddlang build module <import-dir> <projection-dir>`, which verifies the lock and writes declared Rust module files and a hash manifest. Add a new `oddlang assemble <project.toml> <input-store> <candidate-dir>` command that consumes the verified projection and retained blobs from disjoint content-addressed namespaces. The project manifest maps each destination to exactly one producer, fixes crate/feature/target, and lists the hashes of its graph, projection or retained files. Use an empty destination and reject collisions. Execute projection with only semantic graphs, pinned overlays and compiler inputs available. Source maps contain coordinates and digests only. Disallow source text embeds or passthrough nodes. Compare assembled generated bytes with the isolated emitter's manifest and verify Cargo dep-info plus build-script inputs stay within the declared closure. Test a poisoned retained blob offered as generated output, a graph carrying raw implementation text, and symlink/include/build-script substitutions; each must fail. As a positive control, removing the original source checkout after import must still produce the same module. Retain host-bound process, credential, storage and transport implementations by audited source digest. Model their boundaries and test dependencies. Keep external libraries, operational tooling and platform effects visible in the inventory.
- [ ] **Importer agent** extends the phase-3 grammar under a distinct locked profile, `framing-v1`. Keep the original grammar and diagnostics versioned in `docs/language/rust-import.md`. Publish `docs/language/rust-framing-recognizers.md` specifying the accepted AST shapes for inherent methods, associated constants, byte slices, `?`, restricted `map_err` closures, and each approved Serde, thiserror and base64 construct used by the pinned fixture. For every recognized expansion/call record the resolved package, version, item, enabled features, toolchain, relevant attributes and result/error semantics. Test shadowed imports, unknown derive attributes, altered features and unsupported closure bodies for deterministic rejection. Re-run the phase-3 rejection corpus under its original profile.

- [ ] **Codec agent** leads with the complete public `ProbeEnvelope::encode` and `decode` operations in `marmish-core/src/frame.rs`. Extend the importer and Rust/WIT projections with bounded byte lists, fixed integer widths, ordered checks, closed JSON records, exact byte encodings, and a declared canonical padded base64 operation. Bind pinned implementations of codec primitives as native library dependencies and record that trust boundary. Preserve the four `FrameError` outcomes and Rust-facing signatures. Declare `Limits` constants and distinguish declared constants from enforced operation bounds. Use a locked mapping for Serde attributes and recognized library/derive expansions. Fail on an unrecognized path, expansion or configuration. Demonstrate reuse on a second, independent framing fixture. [Framing implementation](https://github.com/Epiphytic/marmish/blob/49fc705408a230bd0ad896248d08dbdd2faad05a/crates/marmish-core/src/frame.rs)
- [ ] **Conformance agent** owns portable framing vectors plus a native consumer and Wasm component runner. Compare exact emitted bytes for empty, arbitrary binary, 16,384-byte and 16,385-byte payloads. Exercise input JSON at 32,768 and 32,769 bytes, whitespace, reordered and duplicate keys, unknown fields, unsupported version, malformed padding and noncanonical trailing bits. Record first named error on overlapping failures and preserve the distinction between wire bytes and decoded values. Demonstrate that a mutant that reorders version and payload checks fails. Compare with independent expectations and untouched upstream Rust.
- [ ] **Integration agent** turns each further phase-5 gap into a named task with path, missing language construct, smaller public fixture, both success and rejection tests, target and acceptance criterion. Examples for later slices include bounded offset arithmetic and numbered enum tags from `marmish-stream`. Close tasks for the requested translation scope before marking it complete. Each newly supported construct must update the language spec, importer, target projection, obligation inventory and work graph. Run `cargo test --locked --offline` with the new Oddlang test targets, then run `scripts/qualify-marmish.sh frame` against original, native regenerated and instantiated Wasm versions.
- [ ] Claude CLI auto review inspects the generated implementation, unchanged original, oracle independence and retained dependencies. Re-run failed cases and review fixes before phase 7.

## Phase 7 — rebuild and qualify the project

- [ ] **Rebuild agent** owns `scripts/qualify-marmish.sh rebuild`. Start with an empty candidate directory. Materialize locked native inputs and generate imported modules from canonical graphs. Rebuild twice in differently named directories and compare graph, source and manifest digests. First compare retained native paths, file modes and blob hashes against their immutable upstream entries. Compare generated files across candidate rebuilds and compare behavior across original and candidate. The generated candidate tree and its lexical ontology may have different digests from upstream. In a disposable git repository stage reconstructed inputs, run `uv run --locked --project tools/code-ontology python tools/code-ontology/index.py update`, stage its outputs and make a local candidate commit. Check that candidate with `check --ref HEAD`. Before a commit exists, upstream's `index.py check` without `--ref` checks the staged tree; identify it by `git write-tree` and label the result staged-only until an immutable candidate commit is verified. Record upstream and candidate commit identities separately, including expected build provenance differences. Compile the complete workspace and installed-feature targets and build the three production binaries. Link a downstream Rust consumer to the regenerated public API.
- [ ] **Validation agent**, working independently from the importer, repeats the phase-5 test/platform matrix, framing oracle and Wasm cases. Compare status, exit codes, declared output bytes, native errors and observable state per scenario. For project-level evidence exercise installed CLI observations and the applicable upstream installed qualification cohorts on isolated fixtures. Use mixed original/regenerated consumers for claimed wire boundaries. Match nondeterministic observations only by specified invariants. Record skipped tests, unavailable hosts, historical/current failures, feature-specific native behavior, and new regressions individually. Source-build results refer to the tested artifacts. [Upstream qualification workflows](https://github.com/Epiphytic/marmish/tree/49fc705408a230bd0ad896248d08dbdd2faad05a/.github/workflows)
- [ ] **Evidence agent** publishes separate counts for regenerated runtime definitions, retained native definitions, unsupported definitions, passed/failed/unobserved obligations, and the exact domains of any exhaustive proofs. Recompute denominators from phase 5. Delete a generated file, change a wire byte, change a retained-file digest and suppress a platform report in separate negative tests. Each must invalidate the associated claim. A passing mixed build establishes a project reconstruction with named generated slices. Full first-party translation requires every in-scope first-party runtime definition regenerated and zero retained or unsupported definitions; keep that outcome open while gaps exist. A universal behavior claim additionally requires exhaustive evidence for every stated domain and effect.
- [ ] **Coverage agent** drives the remaining project through the same loop after the framing pilot. Sort outstanding first-party units by dependency order, group by shared missing construct, implement and independently test each general capability in phase 6, then replace that native unit, rerun phase 7 and publish the changed counts. Keep a pinned capability boundary for external libraries and OS calls. When a unit cannot yet be expressed, publish its blocking example and keep full project translation open. A new port, behavioral change or scope reduction needs a recorded design decision with its effect on the denominator.
- [ ] **Integration agent** runs `scripts/qualify-marmish.sh verify` from the locked inputs in a clean checkout, publishes the coverage table and traces, and updates the work graph. Claude CLI auto reviews the complete chain and verifies that each reported claim follows from the artifacts. Fix, repeat the affected matrix, then record final review disposition.
