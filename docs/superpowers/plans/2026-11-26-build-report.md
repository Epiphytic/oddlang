# Build metadata as a native command

Recover a portable ordered report of build facts. A field is a stable identity with a wire name and typed value source. The first profile supports unsigned integer and integer-list literals, the built package version, target identifier, and the input revision represented by the release. The release supplies its revision pin. This identifies the represented source contract. The actual Oddlang compiler, companion and executable digests belong in the external build receipt. Output is compact JSON followed by a newline on stdout with a successful exit. Ignore runtime environment overrides. Keep output keys and field order contractual.

- [ ] Generate a reusable Rust package component and a checked CLI callback. Read package version from Cargo and capture the actual Cargo target at compilation, including cross-target builds. Lock any generated build script. Reject duplicate field identities and wire names, malformed revisions and unsupported value sources before publication.
- [ ] Run an independent unrelated-package fixture and verify byte-for-byte output through the native executable, including a wire-name mutation, changed package version, alternate source revision, target identity and negative controls. Check that old packages retain their lock hashes.
- [ ] Bind the two native release-report commands in the companion. Compare stdout, stderr and exit code against the original on both ARM64 hosts, check alternate product metadata without reading application source, preserve prior product locks, and publish exact framework and companion pins. Record any unsupported invocation combinations as gaps.
- [ ] Track source recovery separately. The first output contract and the static format list are explicitly authored unless compiler-checked extraction links them to the five original format declarations.
