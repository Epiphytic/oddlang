# Rust source import and translation validation

Execute phases 3 and 4 after the component phases. The first independently written input is a Rust ledger transfer. The imported artifact is an editable Oddlang project accepted by the existing `build` command. A source import locks build inputs and observations. Exact graph recovery from a binary built by Oddlang uses a separately authenticated graph and provenance manifest shipped with the binary. An arbitrary optimized Rust or core Wasm binary has no unique inverse for names, contracts or implementation intent.

## Phase 3 — Deterministic source import and native regeneration

**Owners.** One subagent owns `src/import_rust/` and the grammar in `docs/language/rust-import.md`. A second owns `examples/rust-import/ledger/`, its independent Rust crate, identity map and CLI tests in `tests/rust_import.rs`. A third owns `skills/oddlang-import-cleanup/SKILL.md`. The integrator wires the public CLI in `src/main.rs`. Integrate and request Claude CLI auto review after the negative and positive cases pass.

- [x] Freeze a compilable independent input with a checked Account, error enum, keyed map and transfer function. Pin the unmodified source tree before cleanup. Record a manually authored map of selected crate items, fields, arguments, guards and error variants to IRIs. Keep external facts such as SQL/Avro target names and valid-entry balance bounds in explicit profile inputs and verify those bounds against the Rust constructor. Copy the pinned non-behavior overlays into the output import closure. Derive the transfer logic from the Rust body. A changed priority or arithmetic operand in the input must change the imported behavior.
- [x] Specify version 1 of the accepted syntax and effects before lowering. Retain its fixtures and rejection diagnostics when a later profile opts into recognized library calls and derives. Begin with a single selected module, immutable snapshot reads, first-error returns, widened primitive arithmetic with proven intervals, locals, then a straight-line commit of already checked values. Describe each allowed map lookup and update, guard normalization, unique named error mapping, casts and preconditions. Allow commits only when aliasing, range, later fallibility and read-after-write analysis establish the existing simultaneous assignment semantics. Otherwise issue a stable diagnostic with source span. Require a valid Cargo build under the resolved package, feature set, target, edition, compiler and overflow flags. Parse with pinned Syn, restrict path/type resolution to supported local declarations, explicit primitive/standard types and qualified operations. Reject ambiguous names, custom trait operators, shadowed standard types, unchecked casts, unknown calls, cfg branches and macros in the selected closure until their semantics are implemented. Reject build scripts, generated sources and procedural derives affecting that closure in this profile. [Syn syntax and spans](https://docs.rs/syn/latest/syn/)
- [x] Implement `oddlang import rust <manifest-path> <mapping.toml> <output-dir>`. Publish canonical UTF-8 Turtle rooted at `domain.ttl`, provenance/source map and `import.lock` atomically. The lock identifies original and effective input digests, validated source and overlay closure, toolchain, Cargo.lock, target/flags, importer/profile version, mapping and graph digest. Keep spans, comments and location metadata outside semantic graph bytes. Pin stable guard identities independently of their ordering and reject missing/duplicate mappings. Reject stale provenance or generated artifacts on replay. Restrict lock inputs to relative paths or content identities so clean directories agree.
- [x] Exercise repeat imports from separate directories, harmless whitespace/local renames with updated mapping where needed, reordered guards, duplicate IDs and stale mappings, unsupported side effects and partial output failures. Require byte-identical graphs for equivalent inputs and deterministic diagnostics for the same failing input. A semantic mutation must reach the generated executable. CI runs `cargo test --locked --offline --test rust_import`. Run the public CLI below and compile the emitted `account.rs` in a fresh integration crate without access to the original operation body.

```sh
cargo run --locked --offline -- import rust examples/rust-import/ledger/Cargo.toml examples/rust-import/ledger/mapping.toml target/import-ledger
cargo run --locked --offline -- build target/import-ledger target/import-ledger-native
```

- [x] Ship an optional cleanup skill that accepts a diagnostic, source span and pinned mapping and proposes a reviewable source or mapping patch. Exercise an unsupported guard macro, an ambiguous identity and a patch that silently changes error priority. Require explicit patch acceptance and re-import. Store patch digest and both source digests. Offline replay and validation use stored inputs. The original, pre-cleanup executable supplies the comparison baseline in phase 4. Document escalation to a future compiler-backed frontend if semantic resolution repeatedly blocks a common construct.

## Phase 4 — Translation validation for an explicitly defined behavior

**Owners.** An independent subagent owns the harness and corpus in `tests/rust_translation.rs`, using `tests/support/ledger_oracle.rs` and the [ledger core semantics](../../language/ledger-core.md). A different subagent owns the proof package in `verification/rust-translation/` and proof-runner setup. The coordinator owns `cargo run --locked --offline --manifest-path verification/provider-validation/Cargo.toml --bin translation-verify` and reports. Keep the importer team out of expected-result generation. Have Claude review the actual proof boundary, assumptions and mutant counterexample in auto mode.

- [x] Compare three implementations on identical valid entry states using independent representation adapters. Call the frozen original, compile and call the actual emitted Rust, and run the existing oracle. Compare success or exact first named error and the full poststate including all keys, owner text, unchanged bystanders and error atomicity. Include every guard overlap, missing and identical keys, empty and Unicode keys, signed extrema, overflow and reproducible seeded generation. Replay the protocol obligations against any service or Wasm roles actually claimed. Preserve separate per-role evidence. An edited-source fixture must compare its regenerated output with the original before the edit.
- [x] Spike Kani early using a real positive pair and a guard-reordering mutant. Give both sides the same symbolic signed i64 amount, admissible balances, presence/equality partitions and initial unrelated state. Make the harness link the captured original and regenerated production functions by digest. Prove abstractions separately if the map, arbitrary strings or allocations require reduction. For unbounded map and key claims, establish that each body uses keys only for equality and addressed reads/writes, that lookup preserves presence/value under renaming, and that inserting arbitrary bystanders preserves the result and their contents. Document allocator success and the execution model. Comparing independently rewritten finite models, or executing a few bounded keys alone, qualifies only the modeled domain. [Kani usage and counterexample playback](https://model-checking.github.io/kani/usage.html)
- [x] Record and replay a concrete failure on the mutant, e.g. missing source and negative amount must return SourceMissing first. Add another mutant that updates the debit before an error and detect changed state. Guard against vacuity with reachable-success and each reachable-error witnesses. Pin Kani, its rustc, backend, unwind and timeout settings. Check reachability, unwinding, panics and unsupported operations. Explain any difference between the production and proof compilers/configuration and limit the claimed result accordingly.
- [x] Run `cargo test --locked --offline --test rust_translation` and the new `cargo run --locked --offline --manifest-path verification/provider-validation/Cargo.toml --bin translation-verify` in a clean tree after caching pinned tools. The script imports, regenerates, compiles, runs the corpus, calls `cargo kani --harness transfer_equivalence` from the proof package, checks the expected failing mutant, and archives source/graph/build/harness digests, contract IRIs, observation domain, solver outcomes, restrictions and counterexamples. Make deterministic replay fail on missing or stale reports. Classify each claim as tested, proved over the recorded domain, disproved, or inconclusive. A timeout, unsupported operation or unclosed reduction keeps the wider claim open. Mark a scoped proof milestone complete only for its actual discharged domain. Require the plan coordinator to record a blocker and task for any unfinished all-input claim before downstream work cites it.

- [ ] **Open proof obligation.** Establish that arbitrary key renamings and arbitrary additional bystander accounts preserve both production outcomes and every untouched value. The bounded Kani harness and differential corpus provide evidence only for their respective domains.
