# Basic-command interoperability with mainline Marmish

**Acceptance decision.** On one supported platform, a mainline client must complete basic commands against an Oddlang-generated server, and an Oddlang-generated client must complete the same commands against a mainline server. Both directions must reproduce the reference exit status, response formatting and exact stdout and stderr reliably. Passing closes the basic-command compatibility layer. The broader distribution plan tracks other commands, package APIs and platforms separately.

**Starting point.** Pin mainline at `af54339d250290490d62d4475a77539b7e739071` and the initial companion at `53ece04bad4d12f0a6846ecb652493be7bf92a55`. The companion can generate and compile a seven-member workspace. Existing CLI, record and import receipts cover selected surfaces. Mixed-peer status checks exist. Mixed-peer execution of a basic remote command remains unmeasured. Start on macOS ARM64, where generated builds already have native evidence. Record updated build pins for each candidate. ### 3. Decide compatibility from repeatable observations

- [ ] In each direction run the full corpus once with fresh identities and rooms, then three more times reusing the established pairing. One cold and three warm repetitions follow upstream benchmark practice. Every case must agree with the pinned oracle in every run, and teardown must pass. Any failure voids the attempt. Preserve all attempted outcomes and require a full fresh cold/warm series for qualification.
- [ ] Include the upstream finite benchmark payload as the basic throughput observation in the upstream/upstream control and both mixed directions. Report its verified 262,144 stdout-plus-stderr bytes divided by measured whole-operation time, with cold and warm samples separate. A positive byte count alone cannot establish correctness. No minimum rate was requested.
- [ ] Publish one sanitized receipt per direction plus the reference control. Include case-by-case comparisons, build provenance, peer attribution, elapsed time and cleanup outcomes. Mark the compatibility task done only after both directions pass on the same platform and candidate. Additional platforms and the entire upstream suite remain distribution work. - [ ] **Repair the reference observation.** The two mixed receipts stop during generated setup with exit 125. Retain the cleanup result for each failed attempt. Distinguish the client’s own exit from the outer 330-second watchdog. Keep the watchdog above the observed client wait and record which deadline fires. A timeout always fails the success case.
