# Basic-command interoperability with mainline Marmish

**Acceptance decision.** On one supported platform, a mainline client must complete basic commands against an Oddlang-generated server, and an Oddlang-generated client must complete the same commands against a mainline server. Both directions must reproduce the reference exit status, response formatting and exact stdout and stderr reliably. Passing closes the basic-command compatibility layer. The broader distribution plan tracks other commands, package APIs and platforms separately.

**Starting point.** Pin mainline at `af54339d250290490d62d4475a77539b7e739071` and the initial companion at `53ece04bad4d12f0a6846ecb652493be7bf92a55`. The companion can generate and compile a seven-member workspace. Existing CLI, record and import receipts cover selected surfaces. Mixed-peer status checks exist. At that initial pin, mixed-peer execution of a basic command was unmeasured. See the current checkpoints below for subsequent measured attempts. Start on macOS ARM64, where generated builds already have native evidence. Record updated build pins for each candidate. ### 2. Measure each direction and close observed gaps

- [ ] Run the same harness separately for upstream client → generated server and generated client → upstream server. Start each pairing with clean state. Inventory each side’s client, daemon, worker, setup/provisioning and credential-helper roles actually exercised. Every first-party executable for that side must come from its named build, including setup and helpers. Reject a substituted digest for each role before accepting the run. Bind results to the intended receiver using independent server-side fixture receipts. Prove that substituting the wrong artifact, corrupting output or returning the wrong status fails the comparison.
- [ ] Classify the earliest mismatch against independent reference observations. Track CLI request and response shape, peer identity and authorization outcomes, command lifecycle, output framing, error mapping and exit status as distinct obligations. Record unknowns explicitly. Preserve all attempted outcomes and require a full fresh cold/warm series for qualification.

### Current checkpoints after the composed candidate

Both mixed pairings published their identities and reached activation. The generated client then exited 255 in about 15 ms and wrote 25 bytes to stderr. Investigate local prepare first. In the reverse direction the mainline client exited 255 with a pending result after about 301 seconds. Neither run produced the intended receiver's fixture receipt. Each of two upstream controls matched all 24 case observations, including exact output and attribution. Cleanup verification was blocked in both controls and the generated-server mixed run because host preferences metadata changed. Only the generated-server receipt identifies the Keychain directory. The writer is unknown. Both mixed runs removed their temporary workspaces. The [pinned receipts](https://github.com/Epiphytic/marmish-oddlang/tree/a502b9eba07ff64407655ee170edf381c4f1402f/verification/whole/basic-command-interop) preserve these distinct results.
